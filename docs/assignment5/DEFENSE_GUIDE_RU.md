# Защита Assignment 5

## Главная идея

Facade упрощает большую операцию: допуск машины → выбор места → оплата. Strategy позволяет поменять способ расчёта цены или выбора места внутри этой операции. Поэтому оба паттерна работают вместе.

Старые статусы NEW, PAID, RESERVED описывают состояние сущностей. HourlyPricing и другие стратегии описывают алгоритмы. Смена тарифа не переводит оплату в другое состояние.

## Вопросы преподавателя

**Где Strategy?** PricingStrategy и AllocationStrategy — контракты; по три реализации; PricingPolicy и SpaceSensorGrid — контексты.

**Почему стратегии разные, а не просто коэффициенты?** Hourly растёт линейно; capped перестаёт расти после достижения потолка; demand имеет два часа без доплаты и затем использует датчик. Места выбираются по номеру, расстоянию до лифта или истории использования.

**Где if при выборе?** В PricingSelector и AllocationSelector. Контексты просто вызывают метод интерфейса. Проверки корректности часов и свободных мест — обычные бизнес проверки.

**Что такое setStrategy?** Замена алгоритма в существующем контексте во время работы. Новый объект контекста создавать не нужно.

**Почему не State?** Стратегия выбирает способ работы. State описывает фазу жизни объекта. Оплата PAID не становится REFUNDED из-за смены тарифа.

**Почему не Template Method?** Нет родительского класса с фиксированными шагами и переопределяемыми методами. Контекст хранит отдельный объект и делегирует ему всю операцию.

**Что защищает от внешних изменений?** DemandPricing зависит от OccupancySource, а не от конкретного датчика. В тестах FakeOccupancySource возвращает известное число.

**Как сохраняется цена после сбоя?** До сохранения оплаты BillingRepository пишет PriceQuote с id, hours, amount. Повторная попытка читает quote и не рассчитывает сумму заново. Сам quote не означает списание денег.

**Остался ли Facade?** Да. Его цепочка, статусы, порядок компенсации и публичные методы сохранены. Новые алгоритмы находятся внутри подсистем B и C.

**Как определяется загрузка?** В задании используется отдельное симулированное показание 0–1, которое задаётся пунктом 14. Оно не вычисляется автоматически из трёх броней. Историю использования мест программа читает из сохранённых броней.

**Сохраняется ли выбранный режим после перезапуска?** Нет. Конфигурация текущего сеанса возвращается к hourly/first. Брони, оплаты и уже рассчитанные quote сохраняются. Операция, которая ещё не дошла до цены, использует активный тариф при расчёте.

## Live coding добавить стратегию

Создай новый файл parking/pricing/FirstHourFreePricing.java:

```java
package parking.pricing;
public final class FirstHourFreePricing implements PricingStrategy {
    public int amountFor(int hours) {
        return Math.max(0, DurationRules.requireValid(hours) - 1) * 500;
    }
}
```

Используй `context.setStrategy(new FirstHourFreePricing())`. Код PricingPolicy менять не требуется. Для появления нового пункта ручного меню добавь имя в PricingSelector.manual; для автоматического выбора добавь соответствующее правило в PricingSelector.select. Это изменение политики выбора, а не контекста.
